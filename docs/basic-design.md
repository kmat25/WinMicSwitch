# WinMicSwitch 基本設計書

Windows 10／11 向けの個人用トレイアプリ。通常ユーザー権限で動作し、メインウィンドウを持たない。ビルドと起動手順は [README](../README.md)、クラス構成・Windows API・検証記録は [詳細設計書](detailed-design.md) にまとめる。

## 操作と対象

Windows のアクティブな入力デバイスを対象とする。トレイアイコン、ツールチップ、メニューのチェックは、一般用（Multimedia）の既定入力を示す。

| 操作 | 動作 |
| --- | --- |
| 起動 | 現在の入力一覧、用途別の既定入力、一般用マイクのミュート・入力音量を読み取る。同じ Windows セッションでの二重起動は後から起動したプロセスが終了する。 |
| 左クリック | その時点の一般用マイクのミュートを読み、同じマイクに反転した値を設定する。 |
| アイコン上でホイール | 一般用マイクの入力音量を上下 1 ノッチにつき 2 ポイント調整する（0～100%）。ミュート中も設定音量を調整できる。メニューを開いている間は操作を受け付けない。 |
| 右クリック | 状態を再取得して使用可能なマイクを表示する。 |
| マイク名を選択 | コンソール用（Console）、一般用（Multimedia）、通信用（Communications）の順に既定入力を変更し、各ロールの結果を読み直す。選択先のミュートと入力音量は書き換えない。 |
| 「終了」 | 通知登録を解除してトレイから終了する。Windows のマイク設定は終了時の値を保持する。 |

ロールが分かれているときも、左クリックとホイールの対象は一般用だけである。一般用マイクを一覧で選び直すと、他のロールも同じ入力へ切り替えられる。通話中の切り替えや個別に指定した機器への反映は通話アプリ側の設定と動作に依存する。

## 表示と番号

| 状態 | アイコン | 判定 |
| --- | --- | --- |
| 収音中 | マイク＋番号 | 一般用のミュートが解除され、デバイス通知と対象マイクの音量通知が登録されている。 |
| 消音中 | 斜線付きマイク＋番号 | 同じ条件でミュートが設定されている。 |
| マイクなし | 禁止記号＋「—」 | 一覧取得に成功し、アクティブな入力が 0 件。通知の登録状態にかかわらず優先する。 |
| 状態不明 | 疑問符＋番号または「—」 | 上記以外。読み取りや通知登録に失敗した場合、一般用の既定入力を特定できない場合など。 |

「収音中」は Windows のミュート解除を表す。音声の取得や音量レベルの計測は行わない。ツールチップには設定音量、状態、機器名の順に表示し、状態の表記はメニューと同じ「消音中」「収音中」とする。音量だけを取得できなければパーセントを省く。

マイクは表示名順（大文字・小文字を区別しない）、同名ならエンドポイント ID 順に並べ、更新ごとに 1 から採番する。接続・切断・改名で番号が変わっても、メニューで選んだ機器は項目が保持する ID で特定する。

右クリックメニューには「WinMicSwitch」の見出し、マイク一覧、「終了」が並ぶ。一般用の行にだけチェックと状態が付く。ロールの既定入力が異なる場合、既定なし、または取得に失敗した場合は、見出しの下に 3 ロールの内訳を示す。UI は起動時の表示言語が日本語なら日本語、それ以外は英語を使い、機器名には Windows の表示名を使う。

製品アイコンは状態・番号・DPI・テーマに合わせてコードで描画する。[現行デザインのコンセプト画像](../WinMicSwitch-UI-Concept-v2.png) に、一般用マイクが #2 の場合のメニューと、4 種類のトレイ表示を示す。実際の表示は[アイコンの表示例](tray-icon.png)と[メニューの表示例](tray-menu.png)を参照。

## 外部変更と失敗時の動作

- Windows のデバイス通知と一般用マイクの音量通知を受け、UI スレッドで一覧と表示を更新する。メニュー表示中に更新対象の通知が届けばメニューを閉じる。一般用の入力が変わると、切り替え先のミュートと音量を読み直す。
- 通知登録に失敗すると「自動更新停止」を表示し、読めたミュート値を「最終取得」として示す。次回の状態取得時に登録を再試行する。ホイール入力を登録できなかった場合はメニューにその旨を表示する。
- 明示操作は一度に 1 件だけ処理する。状態更新中に届いた最初の操作は更新後に実行する。入力元が不明なら設定を変更せず警告する。操作中や結果表示中の追加入力、完了時刻以前に記録された入力は破棄する。
- 切り替えに失敗した場合は、ロールごとの設定結果と読み戻した既定入力、選択先の変更前後のミュートを表示する。一部成功時も自動で元に戻さず、実際の一般用マイクを表示する。
- 録音、ネットワーク通信、自動起動、グローバルキーフック、アプリ別の入力指定、設定の永続化は初版の対象外とする。

## 受入確認

以下は確認基準である。実施環境、結果、未確認条件は [詳細設計書の検証記録](detailed-design.md#検証記録) を参照する。

| ID | 確認項目 | 合格基準 |
| --- | --- | --- |
| A01 | 起動・終了 | メインウィンドウを開かずに起動・終了でき、起動前後・終了前後で既定入力とミュートが変わらない。 |
| A02 | 左クリック | ミュート・解除の両方向で Windows の値と表示が一致する。状態取得に失敗した場合は設定しない。 |
| A03 | 外部ミュート | Windows 設定や、Windows が変更を検知するヘッドセット操作に追従する。 |
| A04 | 相互切り替え | 内蔵・USB など 2 台以上を相互に選択し、3 ロールの実際の既定入力が選択先になる。 |
| A05 | 切り替え先のミュート | 異なるミュート状態のマイクを切り替え、切り替え自体では値を変えず、選択先の実際の状態を表示する。選択前のミュート取得だけが失敗しても、対象の利用可能性を確認できれば 3 ロールの変更を続行する。変更後もミュートを取得できなければ状態不明とし、既定入力の変更結果とは分けて伝える。 |
| A06 | 外部の既定入力変更 | Windows 設定や別アプリから変更し、表示・チェック・次の左クリック対象が追従する。ロールが異なる状態も判別できる。 |
| A07 | 抜き差し・番号 | 接続状態に一覧が追従する。残った入力を 1 から振り直し、再接続時も名前・ID 順の連番になる。 |
| A08 | マイクなし・状態不明 | 0 件と取得失敗を区別する。再接続または再取得成功時に適切な状態へ戻る。 |
| A09 | 部分変更・失敗 | 一部ロールの変更失敗、確認失敗、非公開 API 失敗を全体成功と表示しない。Windows と照合できる結果を表示する。 |
| A10 | 競合・連続操作 | トレイ左クリック・メニューのマウス選択・キーボード選択について、元メッセージと操作イベントを対応付け、同じ入力時刻を引き継げることを確認する。単独のバックグラウンド更新中の最初のクリックは、完了後の再確認に基づき 1 回実行する。最初の入力が対応不明なら書き込み 0 回、失敗通知は元の更新・後処理の完了前が 0 回、完了後が 1 回とし、保留中の追加操作で設定処理を始めない。明示操作中の追加クリックは Idle 復帰後の遅延配送でも書き込まない。完了後の別の左クリックは記録時刻が完了境界と同値なら追加書き込み 0 回、新しければ 1 回。Reporting 中の対応不明な追加入力は追加書き込み・追加ダイアログともに 0 回、Idle での対応不明は書き込み 0 回・失敗通知 1 回とする。新旧世代の通知、切断・既定変更・終了との競合も確認する。 |
| A11 | 通話アプリ | Teams などで「既定のデバイス」と個別指定、通話前と通話中を確認し、反映される範囲を記録する。 |
| A12 | 表示・解放 | DPI・タスクバーの明暗・高コントラスト・複数桁番号を確認する。表示更新と終了で通知・アイコンの解放に問題がない。 |
| A13 | ロールが異なる場合のミュート | 一般用を内蔵マイク、通信用を別のヘッドセットとし、左クリックで一般用だけが変化すること、メニューに用途別の番号と名前が表示されることを確認する。Windows のロール・ミュート値と照合し、ヘッドセットを使う通話では左クリックでミュートされない範囲を確認する。コンソール用だけが異なる場合も確認する。 |
| A14 | 通知登録失敗と回復 | デバイス通知・基準ミュート通知それぞれの登録失敗を制御して確認する。ミュート値が読めても疑問符と「状態不明／自動更新停止／最終取得」を表示する。通知が届かない外部ミュート解除後も通常の消音中表示にせず、右クリックで解除値を読み直す。未回復なら最終取得表示を保ち、両通知が回復した後の再取得で通常表示へ戻る。 |
| A15 | 入力音量 | アイコン上の上下ホイールで一般用だけが変化し、上下限とミュートを保持する。Windows での音量変更とツールチップの値も照合する。 |
